# WebSee

폴더, 이미지, TXT/TEXT/JSON/SRT/SMI 텍스트 파일, ZIP/CBZ/RAR/CBR 압축파일을 Chrome 안에서 바로 탐색하는 이미지 뷰어 및 텍스트 편집기 확장 프로그램입니다. 선택한 파일은 외부로 전송하지 않습니다.

## 지원 기능

- 로컬 폴더에서 이미지, TXT/TEXT/JSON/SRT/SMI와 ZIP/CBZ/RAR/CBR을 한 목록으로 열기
- 텍스트 파일 왼쪽 미리보기 및 전용 상세보기(UTF-8, UTF-16, CP949 자동 판별)
- CodeMirror 기반 텍스트 편집, 원본 저장 및 다른 이름으로 저장
- 왼쪽 탐색 트리에서 폴더, 압축파일, 압축 내부 폴더 열기
- Chrome에서 폴더 드래그앤드롭 및 목록 새로고침
- ZIP/CBZ/RAR/CBR 내부 폴더 및 이미지 탐색
- 압축파일을 열면 썸네일과 해상도를 순차적으로 만드는 백그라운드 인덱싱
- 처리한 원본은 즉시 버리고 경량 썸네일만 유지하며, 선택한 이미지만 원본 상세보기로 캐시
- 썸네일과 상세 목록 보기
- 자연스러운 숫자 파일명 정렬
- 확대, 이동, 화면 맞춤, 폭 맞춤, 100%, 회전, GPU 기반 화질 개선
- 옵션에서 활성화할 수 있는 일본어·중국어·영어 이미지 오버레이 번역
- 번역 기능 활성화 시 현재 폴더 이미지와 ZIP·CBZ·RAR·CBR 내부 이미지를 순차 처리하는 일괄 번역
- 전체화면과 옵션에서 활성화할 수 있는 3·5·10초 간격 슬라이드쇼 및 반복 재생
- 파일명, 크기, 형식, 해상도 표시

지원 이미지 형식은 JPEG, PNG, GIF, WebP, AVIF, BMP, SVG, ICO이며, 텍스트는 TXT, TEXT, JSON, SRT, SMI를 지원합니다. 실제 이미지 표시는 실행 중인 브라우저의 decoder 지원 범위를 따릅니다. 암호화된 압축파일, 분할 RAR과 중첩 압축파일은 지원하지 않습니다.

텍스트 상세보기에서 `편집`을 누르면 CodeMirror 편집기가 지연 로딩됩니다. 폴더 또는 드롭으로 쓰기 가능한 파일 핸들을 받은 경우 원본에 저장할 수 있으며, 그 외의 파일과 압축파일 내부 텍스트는 `다른 이름으로 저장`을 사용합니다. UTF-16은 원본 byte order를 유지하고 CP949는 저장할 때 UTF-8로 변환합니다. 일부만 읽은 5MB 초과 파일은 편집할 수 없습니다.

이미지 번역은 현재 열어 본 한 장에만 실행됩니다. 최초 사용 시 텍스트 영역 감지 모델 약 11MB를 받고, 텍스트가 발견되면 Baberu OCR 모델 약 121MB를 추가로 내려받아 브라우저에 캐시합니다. 이후 OCR은 로컬에서 처리하며 원본 이미지를 외부로 보내지 않습니다. `옵션 → 이미지 번역 → 번역기`에서 Chrome 내장 번역(기본값) 또는 macOS Apple 번역을 선택할 수 있으며 개별·일괄 번역에 동일하게 적용됩니다. Chrome 번역에는 최신 Chrome의 `Translator API`를 사용하고 Chrome이 관리하는 언어 모델이 별도로 준비될 수 있습니다. Apple 번역은 아래 도우미 설치가 필요합니다. 저장된 OCR 모델은 메인 툴바의 `옵션`에서 제거할 수 있습니다.

번역기를 바꿔도 저장된 결과를 자동으로 다시 번역하지 않습니다. 개별 이미지는 `다시 번역`, 일괄 번역은 `저장된 결과 건너뛰기`를 해제하면 선택한 번역기로 갱신됩니다. 진행 중인 일괄 번역에서는 번역기 선택이 잠깐 비활성화됩니다.

### OCR 선택

`옵션 → 이미지 번역 → OCR`에서 `기본 (Baberu)` 또는 `macOS Vision`을 선택합니다. 기존 설정은 Baberu로 유지되며, OCR과 번역기는 독립적으로 선택하고 다음 실행에도 유지합니다. 예를 들어 `macOS Vision + Chrome 내장 번역`을 사용할 수 있습니다. 진행 중인 일괄 번역에서는 OCR 선택도 비활성화됩니다.

macOS Vision은 기존 말풍선·텍스트 영역 감지를 유지하고 글자 인식만 macOS `Vision` framework의 정확도 우선 모드로 처리합니다. 영역의 위치와 종류는 그대로 유지하며 개별·일괄 번역 모두 적용됩니다. 이미지는 로컬 Native Messaging으로만 도우미에 전달합니다. 이 경로에서는 Baberu OCR 모델을 내려받거나 실행하지 않으며 영역 감지 모델은 계속 사용합니다. 기존에 내려받은 모델을 자동으로 삭제하지는 않습니다.

같은 영역 안의 OCR 줄바꿈은 번역 전에 이어 붙이고, 화면에서는 영역 폭에 따라 자동 줄바꿈합니다. 일본어·중국어 글자 사이는 공백 없이 연결하며 원문 툴팁과 저장 데이터에는 실제 OCR 결과를 보존합니다.

macOS OCR에는 도우미 프로토콜 v3 이상이 필요합니다. 이전 도우미는 설정에서 업데이트 안내를 표시하며 아래 설치 명령으로 업데이트합니다. OCR 설정을 바꿔도 저장된 번역 결과는 유지하므로 비교하려면 `다시 번역`을 사용합니다.

### macOS 번역·OCR 도우미

macOS 26 이상과 최신 Command Line Tools(Swift 및 macOS 26.4 SDK 이상)가 필요합니다. 회색 설정 영역의 `번역기`에서 `Chrome 내장 번역`, `macOS Apple 번역`, `Apple Intelligence` 중 하나를 선택합니다.

- **macOS Apple 번역**: `lowLatency`를 사용합니다. 원문 언어와 한국어 언어팩이 필요한 기존 번역 모델입니다.
- **Apple Intelligence**: macOS 26.4 이상에서 `highFidelity`를 사용합니다. Apple Intelligence가 활성화되어 있으면 해당 모델을 사용하며 추가 언어팩이 필요하지 않습니다. Apple Intelligence를 사용할 수 없으면 Apple이 기존 모델로 대체할 수 있습니다. macOS 26.4 미만에서는 `macOS Apple 번역`으로 변경하라는 오류를 표시합니다.

두 전략 모두 `TranslationSession` API로 기기에서 처리합니다. 시스템 번역 UI의 온라인/온디바이스 설정과는 별도입니다. 선택한 모델은 개별·일괄 번역에 적용되고 다음 실행에도 유지됩니다. 모델을 바꿔도 저장된 결과는 유지되므로 비교하려면 다시 번역하거나 일괄 번역의 기존 결과 건너뛰기를 해제합니다.

Apple 번역의 원문 언어 감지도 macOS `NaturalLanguage`를 사용하므로 Chrome 번역·언어 감지 모델을 받을 필요가 없습니다. 영역 감지는 기존 브라우저 모델을 사용하며 OCR은 선택한 엔진으로 처리합니다.

1. 먼저 WebSee를 빌드하고 Chrome 확장 프로그램을 새로고침합니다. 새 `nativeMessaging` 권한이 포함됩니다.
2. `옵션 → 이미지 번역`에서 OCR을 `macOS Vision`으로 선택하거나 번역기를 `macOS Apple 번역` 또는 `Apple Intelligence`로 선택하고 설치 안내를 펼칩니다.
3. 안내에 표시된 확장 프로그램 ID를 사용해 WebSee 소스 폴더에서 실행합니다.

```sh
sh native/macos/install.sh <WebSee-확장-프로그램-ID>
```

도우미는 `~/Library/Application Support/WebSee/WebSeeTranslation.app`에 설치되며, 현재 사용자의 Chrome `NativeMessagingHosts`에 해당 확장 프로그램 ID를 허용하도록 등록됩니다. 관리자 권한·외부 서버·상시 실행이 필요하지 않습니다. 로컬 빌드에 ad-hoc 서명을 적용하며 다른 Mac에는 소스에서 다시 설치합니다. 확장 프로그램 ID가 달라졌다면 새 ID로 설치 명령을 다시 실행합니다.

모델 선택은 도우미 프로토콜 v2부터 지원합니다. 이전 도우미가 설치되어 있다면 같은 설치 명령을 다시 실행해 업데이트합니다. 이전 버전에서는 Apple Intelligence를 선택해도 실제로 적용되지 않는 일이 없도록 업데이트 안내를 표시합니다.

4. `macOS Apple 번역`은 `시스템 설정 → 일반 → 언어 및 지역 → 번역 언어`에서 원문 언어(영어·일본어·중국어 중 사용 언어)와 한국어를 다운로드합니다. `Apple Intelligence`는 Apple Intelligence가 활성화되어 있으면 별도 언어팩이 필요하지 않습니다.
5. Apple 번역을 선택하면 도우미 연결을 자동 확인합니다. 연결되지 않으면 `설치 명령 복사`로 현재 확장 프로그램 ID가 포함된 명령을 복사해 실행합니다. 설치 후 WebSee 창으로 돌아오면 연결을 다시 확인하며, `다시 확인` 버튼으로도 확인할 수 있습니다. 언어팩이 없으면 번역 시 준비 안내가 표시되며 다운로드 후 `번역 계속`으로 진행합니다.

도우미는 `chrome.runtime.connectNative()`로 요청받은 문장을 macOS `Translation` framework에, OCR용 이미지와 영역 좌표를 `Vision` framework에 전달합니다. 취소하거나 탭을 닫으면 연결이 끊기고 해당 도우미 프로세스도 종료됩니다. Vite 개발 서버에서는 Native Messaging을 사용할 수 없으므로 macOS 번역·OCR은 설치된 Chrome 확장 프로그램에서 확인합니다. WebSee의 OCR 모델 삭제는 Apple이 관리하는 언어팩을 삭제하지 않습니다.

`폴더 열기`로 연 파일은 쓰기 권한을 허용하면 원본 폴더의 `.websee` 하위에 번역 결과를 JSON으로 저장합니다. 일반 이미지는 `.websee/<이미지 파일명>.json`, 압축파일은 `.websee/<압축파일명>.json` 하나에 내부 이미지 경로별로 기록하며, 원본 크기와 수정 시각이 일치할 때 다음 실행에서 우선 불러옵니다. 메인 툴바의 `옵션`에서 현재 폴더의 저장 용량을 확인하고, 원본이 사라진 번역 데이터만 정리하거나 현재 폴더 데이터를 모두 삭제할 수 있습니다. 이미지 파일만 드래그한 경우에는 `번역` 버튼을 처음 누를 때 원본 폴더를 선택하면 저장된 결과를 먼저 불러오며, 폴더를 선택하지 않으면 번역 결과가 이번 실행 중에만 유지됩니다.

툴바의 `일괄 번역`은 현재 폴더의 일반 이미지와 선택적으로 압축파일 내부 이미지까지 한 장씩 처리하고, 완료된 결과를 즉시 저장합니다. 저장된 결과 건너뛰기가 기본값이므로 중지하거나 Chrome을 닫은 뒤 같은 폴더에서 다시 실행하면 남은 항목부터 이어집니다. 하위 폴더는 일괄 번역 대상에 포함하지 않습니다.

## Chrome에 설치

```sh
npm install
npm run build
```

1. Chrome에서 `chrome://extensions`를 엽니다.
2. 오른쪽 위의 `개발자 모드`를 켭니다.
3. `압축해제된 확장 프로그램을 로드합니다`를 누릅니다.
4. 이 프로젝트의 `dist` 폴더를 선택합니다.
5. WebSee를 툴바에 고정한 뒤 아이콘을 누르면 전체 탭으로 열립니다.

코드를 수정한 뒤에는 `npm run build`를 다시 실행하고 확장 프로그램 카드의 `새로고침` 버튼을 누릅니다.

## 개발 서버

확장 프로그램으로 설치하지 않고 UI를 빠르게 개발할 때는 기존 Vite 서버도 사용할 수 있습니다.

```sh
npm run dev
```

확장 프로그램과 개발 서버 모두 로컬 폴더 접근 권한은 사용자가 폴더를 선택하거나 드롭한 범위에서만 부여됩니다.

npm run typecheck

npm run build
